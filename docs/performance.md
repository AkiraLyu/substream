# 性能测试

测量前先确定目标语言、识别模型、运行设备和代表性音频。比较结果时保持这些条件一致，同时检查字幕准确率，避免仅凭速度选择模型。

## 需要测量的内容

| 项目 | 测量方法 |
| --- | --- |
| 首次字幕延迟 | 从语音开始，到客户端显示第一条有效字幕。 |
| 最终字幕延迟 | 从一句话结束，到该段字幕定稿，包含识别器等待停顿的时间。 |
| 字幕质量 | 与人工核对的文本和时间比较，记录错字、漏字、时间偏差及反复修改的情况。 |
| 启动时间 | 从请求开始识别，到模型就绪。与持续识别时的延迟分开记录。 |
| 文件处理速度 | 记录媒体时长和任务总耗时，并区分音频转换、模型加载、识别及导出。 |
| 资源占用 | 记录 CPU、内存、显存和临时磁盘用量，包含外部程序。 |

每组结果记录模型版本、设备、线程数、输入音频及构建方式。延迟可报告中位数和 P95；P95 表示 95% 的观测值不超过该值。需要比较优化效果时，预热后重复运行，确认变化大于正常波动。

按改动选择测试场景：采集模块关注设备切换和音频丢失；调度模块关注处理积压和实时、文件任务同时运行；长期运行的问题用较长音频观察资源是否持续增长。无需为每次修改重复全部场景。

## 测量框架自身的开销

```bash
cargo run -p substream --release --example ingest_bench
```

该程序使用 20 毫秒音频帧和固定示例字幕，测量协议解码、音频检查及字幕更新的耗时，输出 P50、P95 和 P99。它不加载语音模型，也不包含采集、网络和界面，因此适合比较相关代码修改前后的开销，不能代表实际识别速度或字幕延迟。
