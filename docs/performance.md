# 性能验收计划

性能目标需要模型、硬件、语言与正确性共同约束。当前没有宣称已达到参考对话中的 300 ms、RTF 0.1、GPU 利用率 90% 等数字。

## 当前可重复的框架基线

```bash
cargo run -p substream --release --example ingest_bench
```

20 ms PCM 帧，先预热 1,000 次，再记录 50,000 次，报告解码、校验、demo pipeline、字幕稳定器的 P50/P95/P99 纳秒耗时。它排除了编码、浏览器、采集、队列、native ASR、模型加载与渲染；不能解释为实际 ASR 速度。演示字幕的推理耗时没有识别性能意义。

2026-09-29 在 Intel Core i5-1155G7、Linux、`rustc 1.100.0-nightly (4aa1fbcf4)` 上的一次 release 运行：P50 **334 ns/frame**、P95 **1028 ns/frame**、P99 **1286 ns/frame**。这只是确认基线工具能运行的单次观测，没有控制频率、功耗与后台负载，不作为性能承诺或跨机器回归阈值。

## 实际验收需要的指标

| 指标 | 采集方法 | 初始目标/限制 |
| --- | --- | --- |
| 首个 partial 延迟 | 标注的语音起点 → 接收客户端第一个正确文本 | P95 500 ms 作为待验证目标，允许按模型修订 |
| final 延迟 | 标注的语音终点 → 最终字幕 | 与 endpoint trailing silence 分开报告 |
| 稳定性 | 同一 segment revision 的文本回改距离 | 连同 CER/WER 测量，避免“快但错” |
| 稳态队列 | 入队/出队单调时钟、满队列次数 | 当前年龄阈值 250 ms，超载显式结束 |
| 冷启动 | 配额获批 → 模型 ready | 与稳态延迟分开，不在加载期间采集 |
| 离线 RTF | 完整任务墙钟 / 原媒体时长 | 分别报告解码、模型加载、推理和导出 |
| 资源 | RSS、峰值显存、CPU%、线程、临时磁盘 | 随运行时长不持续增长；含外部进程 |
| 公平性 | 实时同时运行离线任务 | 报告实时 P99 退化及音频缺失，不能只看 GPU 利用率 |

记录 CPU/GPU/驱动、内存、编译 profile、后端和模型哈希、量化、线程、输入语言、信噪比、媒体长度、采样率、帧长和测试轮数。每组做预热与至少五次独立运行。禁止把不同模型、精度或硬件的 RTF 直接排名。

长跑需要覆盖 60 分钟连续音频、纯静音、长句、CJK/拉丁混合文本、蓝牙设备切换、网络消费者停读、浏览器主线程阻塞、取消、内存压力。字幕时间误差与丢帧数量必须和延迟一起报告。手动浏览器验收要检查用户手势、标签页关闭、弹窗重开、正常停止尾帧、原声音继续播放和合成标识。

原生 PipeWire 回调尚未实现，因此当前不能验证“回调无分配”。离线 whisper-cli 仍按任务加载模型、消费完整 WAV；需要常驻后端与分段调度之后，才能讨论高吞吐与资源隔离的达标情况。
